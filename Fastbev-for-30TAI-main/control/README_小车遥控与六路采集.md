# 小车遥控与六路环视单帧采集说明

## 1. 整理后的目录

```text
小车操作流程\
├─ 启动网页版控制台.cmd       # 日常使用只需双击此文件
├─ README_小车遥控与六路采集.md
├─ 参考资料\                  # 电机手册和成功示例
├─ 标注工具\                  # 去畸俯视图车辆中心和朝向角人工标注
├─ 运行程序\                  # Python、网页、配置、FFmpeg和虚拟环境
└─ 采集数据\                  # 每次运行生成的session及六路图片
```

根目录只保留日常启动入口、说明文件和三个分类文件夹。不要随意移动“运行程序”内部的 `.venv`、`runtime`、`config` 或 `web`。

## 2. 最终功能

程序位于：

```text
小车操作流程\运行程序\
```

它不依赖 `demo4car_opencv_lss`，实现：

1. 通过 Windows 中识别到的 `USB-SERIAL CH340` 串口和 Modbus-RTU 控制四个 EMM42 电机；
2. 打开六路环视 USB 相机，排除 TOP 相机；
3. 每按一次 `R`，六个方向各保存一张新图片；
4. 每次采样的六张图片使用相同帧号，例如都叫 `frame_000001.jpg`；
5. Python、FFmpeg、配置、程序和采样结果全部保存在“`小车操作流程`”文件夹中。

新版本不是连续录像模式，不需要按第二次 `R` 来结束采集。

当前推荐使用网页版统一控制台：直接双击根目录下的 `启动网页版控制台.cmd`。

## 3. 六路相机固定命名

当前 USB 接线不变时，来源与目录名固定如下：

| 原序号 | 相机方向 | 输出目录 |
|---:|---|---|
| 01 | 前方 | `CAM_FRONT` |
| 02 | 左前方 | `CAM_FRONT_LEFT` |
| 03 | 右前方 | `CAM_FRONT_RIGHT` |
| 04 | 左后方 | `CAM_BACK_LEFT` |
| 05 | 后方 | `CAM_BACK` |
| 06 | 右后方 | `CAM_BACK_RIGHT` |

已知 TOP 相机未加入这六路配置，程序不会生成 TOP 图片。

不要随意交换相机、集线器或电脑上的 USB 插口。USB 拓扑变化后，DirectShow 设备路径可能改变，需要重新确认映射。

## 4. 每次运行前的安全检查

1. 设备管理器确认存在 `USB-SERIAL CH340`，并与 `运行程序\config\chassis.json` 中的 `serial_port` 一致。当前配置为 `COM3`。
2. 关闭串口助手、旧 Python 程序和其他可能占用该串口或摄像头的软件。
3. 给小车正常供电，检查 RS485 A/B 接线和公共地没有松动。
4. 第一次运动测试必须将四个车轮全部架空。
5. 让人远离车轮，并保持小车电源开关或电源插头触手可及。
6. EMM42 保持 `UART_FUN / 115200 / Modbus`，地址分别为 1、2、3、4。

车轮映射为：左侧地址 1、3，右侧地址 2、4。整车前进方向参数为：1→0、2→1、3→0、4→1。

## 5. 先检查底盘

四轮架空后，双击：

```text
运行程序\check_chassis.cmd
```

该脚本只读取数据，不发送运动命令。输出中应看到四台电机：

```text
serial_mode=2, baud_code=5, checksum=3, reply=None
```

`reply=None` 是当前四台 EMM42 的真实配置，表示控制写指令执行后不返回确认包。程序已经适配该模式，不需要把它改成 `Receive`，也不需要重装 CH340 驱动。

主说明书给出的电机状态掩码为：

- `0x01`：电机使能；
- `0x02`：电机到位；
- `0x04`：电机堵转；
- `0x08`：堵转保护触发。

因此，当前读到的 `0x0081` 表示“已使能、尚未到位”，`0x0083` 表示“已使能、已经到位”；两者都不是堵转。之前版本曾错误地把 `0x02` 到位位当成堵转位，该问题已经修正，不需要清除 `0x0083`。

更新后的检查会直接显示 `enabled/reached/stall/stall_protection`。四台都应满足 `enabled=True`、`stall=False`、`stall_protection=False`；`reached` 可以是 True 或 False。

只有将来真正出现 `stall=True` 或 `stall_protection=True` 时，才需要在四轮架空后运行 `运行程序\clear_stall_flags.cmd`。

## 6. 只测试六路拍照

双击：

```text
运行程序\start_cameras_only.cmd
```

该模式不会打开底盘串口。等待窗口显示：

```text
CAMERAS READY: press R once to save exactly six images.
```

然后：

1. 按一次 `R`；
2. 等待窗口显示 `SAVED frame_000001: 6 images`；
3. 再按一次 `R`，会保存 `frame_000002`；
4. 按 `ESC` 退出。

每次启动程序只建立一个 `session_<时间>` 会话目录。启动时会建立六个相机目录；每次按 `R` 只在六个目录中各增加一张同帧号图片。旧版本的 `takes\take_XXX` 是连续采集结构，新版本不再创建它。

## 7. 输出结构

结果统一写入：

```text
小车操作流程\采集数据\
```

例如连续按两次 `R`：

```text
session_20260812_150000\
├─ images\
│  ├─ CAM_FRONT\
│  │  ├─ frame_000001.jpg
│  │  └─ frame_000002.jpg
│  ├─ CAM_FRONT_LEFT\
│  │  ├─ frame_000001.jpg
│  │  └─ frame_000002.jpg
│  ├─ CAM_FRONT_RIGHT\frame_000001.jpg ...
│  ├─ CAM_BACK_LEFT\frame_000001.jpg ...
│  ├─ CAM_BACK\frame_000001.jpg ...
│  └─ CAM_BACK_RIGHT\frame_000001.jpg ...
├─ metadata\
│  ├─ frame_000001.json
│  └─ frame_000002.json
├─ logs\ffmpeg_CAM_*.log
├─ config_snapshot\
├─ control_events.jsonl
└─ session.json
```

同一帧号在六个相机目录中必须各出现一次。若任意一路没有取得新图，程序不会把这次采样当作完整帧保存，而会在窗口中报错。

## 8. 架空测试小车

先确认 `check_chassis.cmd` 没有报错，再双击：

```text
运行程序\start_bev_capture.cmd
```

程序启动时保持静止。等待六路相机全部就绪后再操作：

| 按键 | 功能 |
|---|---|
| `W` | 按住前进，松开停车 |
| `S` | 按住后退，松开停车 |
| `A` | 按住左转，松开停车 |
| `D` | 按住右转，松开停车 |
| `R` | 先停车，然后保存一帧六路图片 |
| `SPACE` | 立即停车 |
| `ESC` | 停车、关闭六路相机并退出 |

第一次仅做很短的按键测试，检查 W/S/A/D 方向是否正确。默认线速度约 `0.08 m/s`，电机转速上限为 `30 RPM`，不要在方向确认前提高速度。

拍照时建议先松开 W/S/A/D，再按一次 `R`。程序会让底盘保持停车，等待六路相机各产生一张按键之后的新图，然后保存相同帧号。

## 9. 正式采样流程

架空方向测试通过后，将车放到无人的安全场地：

1. 双击 `start_bev_capture.cmd`。
2. 等待 `CAMERAS READY`。
3. 按住 W/S/A/D 将小车移动到采样位置。
4. 松开方向键，让小车停车。
5. 按一次 `R`，等待 `SAVED frame_XXXXXX: 6 images`。
6. 移动到下一个位置，再按一次 `R`。
7. 紧急情况按 `SPACE`，必要时直接切断小车电源。
8. 全部完成后按 `ESC` 正常退出，再关闭小车电源。

不要在车辆运动时关闭命令窗口或用任务管理器强制结束程序。强制终止可能使软件来不及发送停车指令。

## 10. 截图中 `expected 8 response bytes, got 0` 的原因

这个错误不是 CH340 驱动损坏。四台 EMM42 的控制命令应答模式均为 `None`：读寄存器仍会返回数据，但速度、停车等写命令不会返回确认包。

旧程序错误地等待 8 字节确认，因此把正常的“无应答模式”当成串口失败。当前 `emm42_modbus.py` 会在启动时读取每台电机的应答模式；检测到 `None` 时只发送命令并保留 Modbus 总线间隔，不再等待不存在的回包。同步 `0 RPM` 写入验收已通过，四台实时速度均读回 0。

## 11. 六路同步程度

六路为普通独立 USB 相机，不具备硬件同时曝光。程序保持六路相机常开；每按一次 `R`，等待六路各出现一张按键之后的新画面，再组成同一个帧号。

元数据 `metadata\frame_XXXXXX.json` 中记录六路到达时间和 `arrival_spread_ms`。它能保证每次有六张新图，但不能宣称六张图在完全相同的微秒曝光。若算法以后要求严格硬件同步，需要同步触发相机或外部触发器。

## 12. USB 接线变化后的重新配置

仅在相机或 USB 接线变化后执行：

1. 双击 `probe_cameras.cmd`，生成新的 `checks\camera_devices_<时间>.json`；如果怀疑相机驱动或 VID/PID 变化，运行 `probe_cameras.cmd --all` 列出所有非虚拟 DirectShow 视频设备；
2. 逐个使用 `preview_camera.cmd <序号> <JSON完整路径>` 确认方向；
3. 排除 TOP 相机；
4. 运行 `configure_cameras.cmd <JSON完整路径>`；
5. 按顺序填写 `CAM_FRONT`、`CAM_FRONT_LEFT`、`CAM_FRONT_RIGHT`、`CAM_BACK_LEFT`、`CAM_BACK`、`CAM_BACK_RIGHT`。

## 13. 环境损坏时重新安装

正常情况下不需要重新安装。只有 `.venv` 或 FFmpeg 被删除时才执行：

1. 双击 `运行程序\setup.cmd`；
2. 双击 `运行程序\setup_ffmpeg.cmd`。

安装位置和运行结果仍然只在“`小车操作流程`”文件夹内。

## 14. TOP 俯视参考链路

`参考资料\demo4car_top_remote_replay` 是历史 TOP 俯视相机遥控录制与开环回放参考链路，不是日常六路环视采集入口。需要复现该参考链路时，从 `参考资料\demo4car_top_remote_replay` 内运行：

```text
scripts\start_top_remote.cmd
```

该链路的输出写入 `采集数据\top_remote\session_<时间>`。详细说明见 `参考资料\demo4car_top_remote_replay\README_ZH.md` 和 `HANDOFF_ZH.md`。

## 16. 网页版统一控制台（推荐）

### 16.1 启动

确认没有其他程序占用 `运行程序\config\chassis.json` 中配置的底盘串口或六路摄像头，然后双击：

```text
启动网页版控制台.cmd
```

程序会先检查四台电机并打开六路相机。初始化完成后自动打开：

```text
http://127.0.0.1:8765/
```

服务只绑定本机回环地址，局域网中的其他电脑无法直接控制小车。若浏览器没有自动打开，可手动输入上述地址。

### 16.2 页面结构

左侧包括：

- 顶部“开始运行/结束运行并停车”总开关；
- W/A/S/D 和 R 五个屏幕按键；
- 底盘、六路相机和采样帧数状态；
- SPACE 急停按钮与方向键释放按钮。

右侧按车辆方位显示最近一次六路采样：第一排为左前、正前、右前，第二排为左后、正后、右后。每张图上方均标有固定相机目录名。

### 16.3 正确操作顺序

1. 等待页面右上角显示“六路与底盘就绪”。
2. 点击左上方“开始运行”；在此之前 W/A/S/D/R 均被锁定。
3. 按住实体键盘 W/A/S/D，或按住页面上的对应按键控制车辆。
4. 松开方向键会停车。
5. 运动中按一次 R 或点击页面 R 键，会保持当前运动命令并采集一帧六路图片，不再为了拍照先停车。
6. 六路全部保存后，右侧刷新为相同帧号的六张图片。
7. 点击“结束运行并停车”、SPACE 急停、切换到其他窗口、隐藏/关闭页面或浏览器心跳超过 1 秒，都会停车并重新锁定；继续使用时需要再次点击“开始运行”。
8. 完成后先点击“结束运行并停车”，再回到命令窗口按 `Ctrl+C` 关闭服务，最后关闭小车电源。

### 16.4 按键高亮

实体键盘或页面按键被按住时，对应 W/A/S/D 键会发出青色光。R 采样期间显示紫色高亮。W+A、W+D 等组合按键可以同时高亮并执行前进转弯。

### 16.5 边走边拍的实现含义

网页 R 采样运行在独立线程中，不会调用底盘的 `stop()`，也不会把当前速度改为 0。六路相机在服务启动后保持常开；收到 R 后，每路选择一张触发时刻之后到达的新 JPEG，并保存为同一个帧号。

车辆在曝光期间仍然运动，因此图片可能出现运动模糊，这是“边走边拍”的正常结果。普通 USB 相机仍不具备硬件同步曝光能力。

### 16.6 页面延迟指标

右下方主要指标“采样触发 → 六路全部到达 PC 并落盘”定义为：

```text
PC 网页服务收到 R 请求的时刻
    到
六张新 JPEG 全部写入本次 session 的时刻
```

单位为毫秒，字段名为 `request_to_pc_ms`。旁边的“六路到达跨度”是最早与最晚相机新帧到达之间的差值 `arrival_spread_ms`。这两个数都会同时写入 `metadata\frame_XXXXXX.json`。

### 16.7 网页采样目录

网页版沿用六个固定目录：

```text
session_<时间>\images\CAM_FRONT\frame_000001.jpg
session_<时间>\images\CAM_FRONT_LEFT\frame_000001.jpg
session_<时间>\images\CAM_FRONT_RIGHT\frame_000001.jpg
session_<时间>\images\CAM_BACK_LEFT\frame_000001.jpg
session_<时间>\images\CAM_BACK\frame_000001.jpg
session_<时间>\images\CAM_BACK_RIGHT\frame_000001.jpg
```

### 16.8 只预览页面、不连接硬件

需要查看界面但不想打开底盘串口和摄像头时，双击：

```text
运行程序\preview_web_remote.cmd
```

页面会明确显示 `SIMULATED / PREVIEW`，采样产生的是界面占位图，不写入正式数据集。实际采集必须使用根目录的 `启动网页版控制台.cmd`。

### 16.9 常见问题

- 网页打不开：检查启动窗口是否显示 `http://127.0.0.1:8765/`；若端口被占用，先关闭上一次服务。
- 页面提示本地服务断开：不要继续按键，回到命令窗口查看错误。
- 页面突然锁定：通常是窗口失焦或心跳超时，这是安全停车机制；确认车辆已经停止后再次点击“开始运行”。
- R 没有保存：必须先点击“开始运行”，且上一帧六路采样必须已经完成。
- 图片没有刷新：检查命令窗口和当前 session 的 `logs\ffmpeg_CAM_*.log`。
- 启动时报 “Configured six-camera sources are not all present”：当前 Windows 没有识别到配置中的六路车载相机。先确认六个车载相机都已连接并未被其他软件占用；若怀疑驱动或设备名变化，运行 `运行程序\probe_cameras.cmd --all`，按新列出的设备源重新预览和配置。
